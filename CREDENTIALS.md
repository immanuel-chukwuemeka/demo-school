## Parent Scratch PINs (result checker)

PINs are 10-digit numeric strings, one per Primary/Secondary student (110 PINs), stored in the
`scratchPins` collection (document **ID = PIN**). The seed writes the first 15 to `server/sample-pins.txt`.
Any Secondary PIN also works — e.g. find one for class `ss1`..`ss3` or `jss1`..`jss3`:

```text
server/sample-pins.txt      ← generated by `node seed.js`
```

**How the checker works:** enter any valid PIN + matching admission number → verifies ≤3 attempts
for the current term (First) → fetches `results/2026-2027_first/{classKey}/{studentId}` → pretty
report with print + PDF. Pins cannot authenticate (they only unlock reading of published results).

## Data seed command

```bash
cd server
node seed.js --no-auth   # Firestore content only (fast, no Auth quota)
node seed.js             # Firestore + 1 admin + 30 staff + 210 students (Auth)
```

Wipe & reseed anytime (delete the collections via console, then re-run).

## Secrets (never commit)

- `server/serviceAccountKey.json` — Firebase admin SDK key (`.gitignore`d). Regenerate in
  Project Settings → Service accounts if lost.
- `.env.server` — server-side config (adminsdk client email + project id).
- `.env` / `public/js/firebase-config.js` — **public** web config (safe by design).

## Enabling one-time setup

1. Firebase Console → Authentication → Sign-in method → **Enable Email/Password**.
2. Firestore rules + hosting deploy: `firebase deploy --only firestore:rules,storage,hosting`.
